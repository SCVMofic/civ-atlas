# 后续实施计划：验收收口与 Simulation Boundary

- 适用分支：`main`
- 计划基线：当前 `main`（审查时最新提交 `96a56d68714f72d2b3c28586fd65615f3c299e39`）
- 原则：**Behavior Preservation First, Architecture Improvement Second**
- 范围：先收口 TASK-007 的验收缺口，再完成最小 Simulation façade；不在本计划内重写文明算法。

## 目标与非目标

### 目标

1. 让手机端冒烟测试的名牌点击路径确实命中目标元素，并可检测坐标兜底是否被触发。
2. 让重构报告准确反映已完成工作与剩余风险。
3. 建立一个不改变行为的 `Simulation` façade，统一文明模拟的创建、运行和结果出口。
4. 每次迁移一个调用点，以确定性、存档兼容和端到端冒烟测试为护栏。

### 非目标

- 不重写或整理 `src/gen/civ/**` 内的生成/推演算法。
- 不改变 RNG 调用顺序、种子处理、稳定 ID、事件顺序、年份边界、干预语义或文明历史。
- 不修改 `SAVE_FORMAT`、`GENERATOR_VERSION` 和存档字段。
- 不以 `App.tsx` 行数作为验收指标。
- 不在这一阶段引入新的事件总线、插件式系统或全面 mutation 架构。
- 不将既有性能预算超标描述成通过；性能债单独登记。

## 执行顺序

## TASK-007D — 冒烟点击路径与报告收口

**目的：** 修正测试代码中的选择器插值问题，避免测试因自动回退而产生虚假的稳定性信心。

### 修改

1. 检查 `scripts/replay-check.ts` 手机端“结盟 → 选择名牌 → 重推 → 撤销”流程。
2. 将名牌选择器改为真正插入 `tgt.kind` 与 `tgt.id` 的模板字符串。
3. 记录点击路径：首选元素定位点击成功时标记为 element path；发生回退时记录 fallback path。正常验收运行应能确认元素路径实际命中，而不是仅凭最终结果通过。
4. 对目标元素增加必要的可见性/可点击等待；保留坐标兜底，但不能让兜底掩盖元素定位持续失败。
5. 更新 `docs/refactor-report.md` 的旧 §10 计划文字，明确 TASK-007A/B/C 已完成，并将遗留事项移到“已知问题 / 后续计划”。
6. 将验收结论分成三类：功能断言、测试可靠性、性能预算。性能预算失败不得归类为功能失败，也不得在报告中算作全绿。

### 验收

- 手机端“结盟 → 重推 → 撤销”连续运行至少 3 次。
- 日志/断言确认目标名牌元素选择器实际命中；若走坐标兜底，测试结果应显式标出。
- `pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm smoke` 均记录结果。
- `scripts/fingerprint.ts --check` 仍为 21 组一致。
- 将拖动帧预算（16 ms）与基线差异继续作为已知性能债，不以调整阈值掩盖结果。

### 提交建议

`test(smoke): make mobile plate targeting observable and reliable`

## TASK-008A — 绘制 Simulation 调用图与边界清单

**目的：** 在动代码前明确 façade 包装什么、不包装什么。

### 修改

1. 盘点 `CivSim`、`generateCiv()`、`EventScheduler`、`EventStore` 的定义、创建点和所有调用者。
2. 记录现有生命周期：创建模拟对象、初始化文明、按年份推进、应用干预、生成时代/历史结果、序列化或返回结果。
3. 区分纯计算与 UI/Worker 编排；明确 façade 不应依赖 React、DOM 或 UI store。
4. 在报告中列出输入、输出、错误行为、可变对象所有权及调用顺序；若存在多个不一致入口，先记录差异，不要在 façade 中顺手统一其行为。

### 验收

- 有一张简洁的调用关系图或表格。
- 每个现有调用点都被列出，并注明计划迁移的 TASK。
- 未修改 `src/gen/civ/**`、存档格式、生成器版本或算法。
- 这一步只产出文档/测试辅助，不改变运行行为。

### 提交建议

`docs(simulation): map existing lifecycle and call sites`

## TASK-008B — 建立最小 Simulation façade

**目的：** 给现有文明模拟生命周期提供稳定入口，不重写内部实现。

### 设计约束

1. façade 只包装现有 `CivSim` / `generateCiv()` 路径；内部仍调用当前实现。
2. 只暴露当前调用者真正需要的操作与结果，不复制一份文明状态，不增加与现有对象竞争的第二真值。
3. 不改变任何算法调用顺序、RNG 消耗顺序、事件先后、年份范围或干预应用顺序。
4. 不让 UI 直接依赖 façade 内部的 `EventScheduler` / `EventStore` 细节；但也不在此任务重写这些类。
5. 明确对象所有权与生命周期：谁创建、谁推进、何时结束、结果是否可继续修改。
6. 错误按当前行为向上传递；不新增静默恢复或自动重试。

### 测试

- 为 façade 增加单元测试，覆盖最小生命周期与错误传播。
- 对同一组输入分别走旧入口与 façade，逐字段比较输出。
- 执行 `tests/determinism.test.ts`、`tests/regression-determinism.test.ts` 与 `scripts/fingerprint.ts --check`。
- 执行存档相关测试，确认 `SAVE_FORMAT` 与 `GENERATOR_VERSION` 不变。
- 执行 `pnpm typecheck`、`pnpm test`、`pnpm build`。

### 验收

- façade 测试通过，旧入口/新入口结果一致。
- 21 组基线指纹全部一致。
- 不改 `src/gen/civ/**` 的算法实现。
- 无新增未处理 Promise、重复状态源或 UI 依赖。
- 性能数据与改动前对照；如有回归，先解释或回退，不把它归因于噪声后直接放行。

### 提交建议

`refactor(simulation): add behavior-preserving facade`

## TASK-008C — 单调用点迁移

**目的：** 通过一次迁移一个调用者，证明 façade 在真实路径上可用。

### 执行方式

1. 选择最简单、边界最清楚的一个调用点。
2. 只把该调用点改为 façade；其他调用点继续走旧入口。
3. 运行相关单测、确定性指纹与对应冒烟路径。
4. 对比结果与耗时，记录差异。
5. 通过后再迁移下一个调用点；每次独立提交，避免多个迁移混在一起难以定位回归。

### 验收

- 每个调用点有明确的迁移记录和回归结果。
- 不允许为了适配 façade 而同时重写算法模块。
- 任一调用点无法保持行为时，暂停迁移并重新审查 façade 边界。

### 提交建议

`refactor(simulation): migrate <caller> to facade`

## TASK-009 — 全量回归、性能基线与阶段冻结

**目的：** 判断 façade 是否已经形成稳定边界，决定是否允许进入后续系统级迁移。

### 必跑检查

- `pnpm typecheck`
- `pnpm test`
- `pnpm build`
- `pnpm stress`
- `pnpm smoke`
- `scripts/fingerprint.ts --check`

如果仓库脚本或环境不支持其中某项，报告必须写明原因和替代验证，不能把未运行写成通过。

### 报告必须包含

- 每个命令的实际退出状态、用例数/耗时（若有）及失败详情。
- 21 组确定性指纹结果。
- 存档格式和生成器版本是否保持不变。
- 迁移前后的关键性能对比。
- 未解决问题：软件渲染下拖动预算、stress 中已超预算的项目、名字生成墙上时钟断言、是否需要建立 `bench/` 目录与内存指标。
- 明确列出尚未迁移的调用点与下一阶段风险。

### 放行标准

只有在确定性、存档兼容、错误路径、冒烟功能和报告一致性都通过后，才冻结 Simulation façade 边界。性能预算已知超标可以作为独立债务保留，但必须清楚标注，不能写成全项通过。
