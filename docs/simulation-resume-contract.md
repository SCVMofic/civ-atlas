# 恢复推演的语义契约(TASK-011B)

- 依据:`docs/simulation-event-audit.md`(010A 审计 + 011A 证据)。
- 目的:在动事件语义之前,把"恢复推演(`CivSim.fromCiv` + `run`)**承诺**什么、**允许**什么、
  **禁止**什么"写成一条可执行、可复查的契约。
- 本文件是**设计决策记录**,不改任何代码。

---

## 1. 两种一致性,我们承诺哪一种

| | 含义 | 实测(011A,24 组) | 本契约 |
| --- | --- | --- | --- |
| **强一致性** | 恢复后与不中断运行的**事件执行顺序**也完全一致 | **22/24 不同** | ❌ **不承诺**(见 §2 理由) |
| **结果一致性** | 允许内部顺序不同,但**可观察结果**必须一致 | **24/24 一致** | ✅ **承诺** |

### 1.1 为什么强一致性不能作为承诺

1. **它本来就不是现有语义的一部分**。`CivSim.fromCiv` 的注释写明"不需要保存事件堆"(sim.ts:312-313);
   存档(`SAVE_FORMAT`)只存 `Civ`:log / checkpoints / annals / 各层归属 —— **没有任何一处记录或暴露事件顺序**。
2. **它已经事实上不成立**,而且不是"偶发":011A 在 24 组里 22 组观察到顺序不同,
   包括"哪些事件被重新造出来"这种结构性差异(恢复路径从成品重建事件,一口气跑里有些事件早已作为过期事件被丢掉)。
3. **要把它变成承诺,代价远超收益**:候选方案(保存 `seq`、给同刻事件定义显式排序键)都要求
   **还原原运行期间由动态事件链产生的预约历史** —— 011A 的证据显示这个历史**不可能**从单个计数器还原
   (恢复路径重建出来的事件集合与一口气跑就不是同一套)。而且这会动到调度器,属于本阶段明确排除的范围。
4. **产品语义没有依赖它**:日志/史事/存档/命名/时间轴全部由"结果"推导,没有消费者读事件顺序。

### 1.2 承诺的结果一致性,具体是哪几样(逐字段)

恢复推演与一口气跑必须**完全一致**:

| 项 | 比较方式 | 现有护栏 |
| --- | --- | --- |
| ChangeLog | `size` + `year` / `region` / `layer` / `value` / `cause` **逐字段逐条**(含顺序) | `tests/sim-resume-order.test.ts`;各 `civ-*.test.ts` 的 `expectResumeSame` |
| 史事 annals | 逐条、含顺序(JSON 比对) | 同上 |
| 检查点 | 年份序列 + 每个检查点的民族层/国家层逐字节 | 同上 + `tests/civ-sim.test.ts:231` |
| 最终归属 | 民族层(`culture`)与国家层(`polity`)逐字节 | 同上 |
| 最终 `Civ` 的派生数据(名字、道路、地名、人物、信仰…) | 由上面几样推导 ⇒ 一致性随之成立 | 指纹 21 组 + 确定性回归 |

---

## 2. 允许差异(明确写下来,免得被当成"没保证")

恢复推演**可以**与一口气跑不同:

1. **事件执行顺序**:同刻事件的先后、以及不同刻之间"哪些事件真的被处理"。
2. **事件集合**:恢复路径会**重新预约**一些一口气跑里早已过期丢掉的事件(它们执行后通常是空操作),
   也可能**不再重建**某些由动态事件链排出来的事件。011A 的轨迹条数不同(23 vs 21)就是这么来的。
3. **handler 的执行次数**(随之而来)。
4. **切开那一刻(`t == cut`)的边界**:恢复路径会把"本该更早发生"的事件钳到 `cut` 重新排队
   (sim.ts:364 的 `Math.max(t, now, floor)`),所以 `cut` 这一 tick 上可能出现一口气跑里已经处理过的事件。
   011A 实测这种边界情形下结果仍一致,但**本契约不为 `t == cut` 单独承诺** —— 要下结论得先扫一遍。

**这些差异一律不得泄漏到 §1.2 的任何一项。** 一旦泄漏,就是缺陷,按缺陷处理。

---

## 3. 禁止差异(红线)

1. **不得放宽结果一致性**:不许以"内部顺序可以不同"为理由,把 §1.2 里任何一项改成"允许不同"。
   要改必须走设计审查,并说明为什么产品可以接受。
2. **不得改存档语义**:`SAVE_FORMAT = 1`、`GENERATOR_VERSION = 9` 不因本契约变化;
   恢复推演仍然只依赖 `Civ` 里已有的字段。
3. **不得靠"重试 / 多跑几次"掩盖差异**:顺序差异是确定性的(011A 的复现不依赖机器负载),
   不许用重试把失败盖过去。
4. **不得动 RNG、公开行为、错误传播**:恢复路径的错误传播与一口气跑一致(异常照抛,不吞)。

## 4. 怎么守(现有 + 新增的护栏)

| 护栏 | 守什么 |
| --- | --- |
| `tests/sim-resume-order.test.ts`(011A 新增) | ①顺序差异真实存在(精确到事件序列,防止有人"以为一致"而写错契约)②结果一致性(ChangeLog 逐字段 + annals + 检查点 + 归属) |
| `tests/civ-sim.test.ts:231`、`civ-wars` / `civ-politics` / `civ-dynasty` / `civ-assimilation` / `civ-cities` / `civ-polities` / `civ-interventions` 里的 `expectResumeSame` | 多个切点(含"分裂 / 合并 / 复国 / 改朝换代 / 毁城重建 / 迁徙同化 / 干预前后"那一刻)的结果一致性 |
| `scripts/probe-resume-order.ts` | 扩大扫描用(更多种子 / 切点 / 精细度;带干预、带地形大事的组合**尚未扫**) |
| 21 组指纹 + `tests/regression-determinism.test.ts` | 一口气跑这条路径本身没被改动 |

---

## 5. 本契约**没有**覆盖的范围(不许当成已保证)

- **未扫**:带**干预**、带**地形大事**、其他**精细度**(12k / 200k)、`landFraction` / `plates` 等参数变化下的恢复;
  011A 只扫了 `DEFAULT_PARAMS`(36000 地块)、无干预、无大事的 6 个种子 × 4 个切点。
  现有 `expectResumeSame` 覆盖了干预与大事的若干切点,但那是"结果一致"的采样,不是全参数覆盖。
- **未证**:§1.1 里"多出来 / 少了的事件都是空操作"这一层是**推断**(据轨迹所见),
  要坐实得逐事件追一遍。它不影响本契约的承诺(承诺只看结果),但影响"要不要修"的判断。
- **未承诺**:`CivSim` 内部状态(`processed`、事件堆、各系统模型)在恢复后的形态。

## 6. 将来若要动事件语义 / mutation 边界(下一阶段的前置条件)

1. 先跑 `npx tsx scripts/probe-resume-order.ts`(或扩大它的样本)与 `pnpm test`,确认**结果一致性**没被破坏。
2. 若要让契约更强(例如承诺顺序一致),那是**新需求**:需要单独设计(怎么保存/重建预约历史)、
   单独验证、单独审查 —— 不许顺手夹在重构里。
3. 若要把契约放宽(例如承认某类结果差异),必须先说明**产品为什么可以接受**,并在本文件里改掉,
   同时更新 §4 的护栏 —— 不许只改测试让它变绿。

# TASK-011C 决策:**本阶段不改代码**

计划要求:011A 复现差异后,先比较候选方案再决定;"如果证据显示没有可确认的缺陷,
则以'不改代码'的决策报告结束 011C"。**结论:不改。**

## 1. 判定"缺陷"的口径

按 §1.2/§3:只有差异**泄漏到承诺项**(ChangeLog 逐字段 / annals / 检查点 / 最终归属)才算缺陷。
011A 的实测:顺序差异 **22/24**,泄漏 **0/24**。**没有观察到可确认的缺陷。**

## 2. 三个候选方案逐个评估(结论都是"不做")

### 候选 A:恢复时保留 / 重建预约序号(`seq`)

- **不成立,而且 011A 的证据直接证伪了"存一个计数器就够"**:恢复路径重建出来的**事件集合**与
  一口气跑就不是同一套(轨迹条数 23 vs 21,内容也不同)—— 有些事件在恢复侧是**新造**出来的
  (从 log/annals 反推),在原来那一侧早作为过期事件丢掉了;另一些由动态事件链排出来的事件
  在恢复侧**没有重建来源**。也就是说原运行期的预约历史**不是**一个计数器能还原的,
  它取决于当时各系统在 handler 里动态排了些什么。存 `seq` 只能让"两边都有的事件"的编号对上,
  对"两边事件集合不同"这件事无能为力 —— 而后者恰恰是 011A 观察到的主要差异。
- 另外它要改 `Civ`/存档的字段,触碰 §3 红线 2。

### 候选 B:为同刻事件定义稳定的显式排序键(不用 `seq`)

- 这会**改变现有语义**:"先预约先处理"(sim.ts:378,`tick * SEQ_SPAN + seq`)是所有既有确定性
  结果的基础 —— 21 组指纹、`regression-determinism`、全部 `civ-*.test.ts` 的逐字节断言都建立在这条上。
  换成任何别的键(按事件类型、按州号……)都会改变**一口气跑**的日志顺序 ⇒ 结果本身变了,
  必须 bump `GENERATOR_VERSION` 并解释,代价与收益完全不成比例(为修一个**不可观察**的差异)。
- 而且它**未必解决问题**:排序键只能定"两边都有的事件"的先后,定不了"事件集合不同"。

### 候选 C:限定并记录恢复语义的保证范围(**采纳**)

- 就是 §1 那份契约:承诺**结果一致性**(有测试守),明确**允许**内部顺序差异,并写明**未扫范围**。
- 为什么它比 A/B 更安全:**不碰调度器、不碰存档、不碰 RNG、不改变任何既有结果**;
  同时把"哪些差异可以接受"从"没人写下来"变成"白纸黑字 + 有测试钉住"。
  这也正是 011A 的测试在做的事(顺序差异真实存在 + 结果一致真实存在,两条都钉住)。

## 3. 遗留风险与它的边界(照实登记)

| 风险 | 现状 | 边界 |
| --- | --- | --- |
| 顺序差异可能在**未扫**的组合(干预 / 地形大事 / 其他精细度 / 其他参数)下泄漏到结果 | **未扫,不知道** | 有探针可扩扫(`scripts/probe-resume-order.ts`);现有 `expectResumeSame` 在干预与大事的若干切点上验的是结果一致 |
| "多出来 / 少了的事件都是空操作"只是**推断** | 未逐事件坐实 | 它不影响契约的承诺(承诺只看结果),但若将来要"修顺序",必须先把它坐实 |
| 内部顺序差异会让"逐事件调试"变难 | 事实 | 调试时用探针看轨迹,不要假定两条路径的事件序列相同 |

**什么情况下要重新评估(触发条件)**:① 探针在**带干预 / 带地形大事**的组合下扫出结果差异;
② 将来有消费者开始依赖事件顺序(例如新的回放 / 事件流 API);③ 有人要给 `CivSim` 加"顺序也一致"的承诺。
三者任一出现,再按 §6 的流程重新设计 —— **不许顺手改调度器**。
